## 4. Normalization Design Notes

The profiler intentionally performs only lightweight exploratory normalization. These transformations should not automatically become production normalization rules.

Production preprocessing should:
- preserve every original raw field;
- generate multiple representations instead of replacing the original value;
- normalize case and whitespace consistently;
- standardize only abbreviations supported by observed dataset noise;
- preserve meaningful geographic information;
- preserve numeric/address components;
- avoid collapsing distinct businesses merely because their normalized names are identical;
- validate normalization changes through collision analysis.

### Important precision constraint

The challenge uses macro F0.5, so false-positive entity merges are particularly costly. Aggressive normalization should therefore be validated against collision patterns before being used for matching.

Example: `ABC Hospital Mumbai` and `ABC Hospital Pune` should not become the same entity simply because `Mumbai` and `Pune` were removed.

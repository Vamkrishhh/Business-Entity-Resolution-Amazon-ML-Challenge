# Business Entity Resolution — Member 3 Pipeline

Self-contained inference pipeline for the Amazon ML Challenge
Business Entity Resolution track.

---

## 1. Problem

Given three sources of business entity records (Source 1, Source 2,
Source 3), identify which entities across sources refer to the same
real-world business.  The output is:

- `matching_results.tsv` — for each Source 1 entity, the matched
  Source 2 / Source 3 entity IDs at or above the decision threshold.
- `candidate_pairs.tsv` — for each Source 1 entity, all candidate
  entity IDs generated by the blocking step (superset of matches).

## 3. Methodology Summary

### Normalization (`normalize.py`)

Each of the three fields is reduced to a canonical lowercase string:

| Function | Input | Key steps |
|---|---|---|
| `normalize_name` | business name | Unicode NFKC, casefold, `&` → `and`, punctuation → spaces, legal-suffix canonicalization (`Pvt Ltd` → `private limited`) |
| `normalize_address` | business address | Unicode NFKC, casefold, punctuation → spaces, abbreviation expansion (`rd` → `road`, `ave` → `avenue`) |
| `normalize_country` | country name or code | Alias table → ISO 3166-1 alpha-2 (`Germany` → `de`) |

### Candidate Generation / Blocking (`pipeline.py`)

Candidates are generated by exact country-code blocking: Source 1
entities and target entities (Source 2 + Source 3) are indexed by
their normalized country code, and only same-country pairs are scored.
This gives O(n × k) pair comparisons where k ≪ N.

### Feature Engineering (`features.py`)

`build_features(left, right)` produces 13 float features in [0, 1]:

**Name features (6)**
- `name_token_jaccard` — Jaccard similarity of word-token sets
- `name_char3gram_jaccard` — Jaccard of 3-char n-gram sets
- `name_char4gram_jaccard` — Jaccard of 4-char n-gram sets
- `name_length_ratio` — min/max character-length ratio
- `name_prefix4_match` — binary: first 4 chars match
- `name_exact_match` — binary: full strings identical

**Address features (5)**
- `addr_token_jaccard` — Jaccard of address word-token sets
- `addr_char3gram_jaccard` — Jaccard of 3-char n-grams
- `addr_number_overlap` — fraction of left numeric tokens found in right
- `addr_length_ratio` — min/max length ratio
- `addr_exact_match` — binary: full strings identical

**Country features (1)**
- `country_exact_match` — binary: ISO codes agree

**Cross features (1)**
- `name_addr_combined` — 0.6 × name_token_jaccard + 0.4 × addr_token_jaccard

### Matching Model (`matcher.py`)

`EntityMatcher` wraps a scikit-learn pipeline:

```
StandardScaler → GradientBoostingClassifier
    n_estimators = 300
    max_depth    = 4
    learning_rate= 0.05
    subsample    = 0.8
    random_state = 42
```

The model is trained separately on labeled candidate pairs from the
training set and saved as `output/matcher.joblib`.  The inference
pipeline loads this file at startup.

## 4. How to Reproduce

### 4.1 Install dependencies

```bash
pip install -r requirements.txt
```

### 4.2 Train the model (separate step — not part of this pipeline)

Use labeled training pairs (from `train_source*.tsv` and
`train_ground_truth.tsv`) to train and save the matcher:

```python
from src.normalize import normalize_name, normalize_address, normalize_country
from src.features import build_features
from src.matcher import EntityMatcher

# Build feature rows and labels from training data, then:
matcher = EntityMatcher()
matcher.train(feature_rows, labels)
matcher.save("output/matcher.joblib")
```

### 4.3 Run inference

```bash
python src/pipeline.py \
  --source1 dataset/test/test_source1.tsv \
  --source2 dataset/test/test_source2.tsv \
  --source3 dataset/test/test_source3.tsv \
  --output  output \
  --threshold 0.85
```

**Required arguments:**

| Argument | Description |
|---|---|
| `--source1` | Path to test Source 1 TSV |
| `--source2` | Path to test Source 2 TSV |
| `--source3` | Path to test Source 3 TSV |
| `--output` | Output directory (created if absent) |
| `--threshold` | Match probability cut-off (default: 0.85) |

**Prerequisite:** `output/matcher.joblib` must exist (trained model).

### 4.4 Expected outputs

```
output/
├── matching_results.tsv   # source1_entity_id \t matched_entity_ids
└── candidate_pairs.tsv    # source1_entity_id \t candidate_entity_ids
```

## 5. Input TSV Schema

All source files are tab-separated with a header row.

| Column | Type | Description |
|---|---|---|
| `entity_id` | str | Unique entity identifier (e.g. `S1-00001`) |
| `business_name` | str | Raw business name |
| `business_address` | str | Raw business address |
| `country` | str | Country name or ISO code |
